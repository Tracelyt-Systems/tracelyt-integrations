# Security Policy

Tracelyt Systems takes the security of its open-source observability integrations seriously. This document outlines our vulnerability disclosure process.

---

## 1. Supported Versions

| Branch / Phase | Supported | Security Notes |
| :--- | :--- | :--- |
| `main` (Foundation Baseline) | :white_check_mark: | Active repository development baseline |

---

## 2. Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you discover a potential vulnerability, exposed credential, or insecure integration pattern in `tracelyt-integrations`, report it responsibly:
- **Private Reporting**: Use GitHub's private vulnerability reporting feature on the repository, or email [security@tracelyt.io](mailto:security@tracelyt.io).
- **Include**:
  - Detailed description of the vulnerability.
  - Affected integration, configuration example, or component.
  - Potential impact assessment.
  - Reproduction steps or proof-of-concept.

---

## 3. Vulnerability Response Timeline

- **Initial Response**: Within 48 business hours of receipt.
- **Triage & Reproduction**: Within 5 business days.
- **Remediation**: Fix developed and validated in private repository.
- **Public Disclosure**: Coordinated disclosure after patch release.
